# Execution Protocol

This plan runs **unattended**. The guiding principle is **keep making progress**: resolve what
you can, amend what is wrong, defer what is heavy, and never halt over a single fixable issue.

Do not edit this file. Do not copy it into `index.md`.

## Per stage

1. **Pick the stage.** Read `state.json`. If a stage is `IN_PROGRESS`, a previous run died
   mid-stage -- resume and finish it (inspect the working tree for partial work). Otherwise
   re-examine any `BLOCKED` stage whose `blocked_by` items are all resolved. Otherwise take the
   first `PENDING` stage whose `depends_on` are `DONE`.
2. **Read the stage brief.** Follow its links to `resources/` or `stages/NN-name/` only if it
   points you there. Do not pre-read reference material you were not sent to.
3. **Orient.** Read the tail of `journal.md` for what the last run did. If the stage cites a
   decision, read that entry in `decisions.md`.
4. **Resolve ambiguity yourself.** There is no user to ask. Pick the interpretation that fits
   the codebase and existing conventions, record it in `decisions.md`, and proceed.
5. **Implement.**
6. **Validate.** Run the stage's verification and the test suite. GATE lines must pass; REPORT
   lines are measured and their values written to `journal.md`. If anything fails, triage below
   -- do not stop. **A green command is not evidence.** For every GATE value, name the input it
   was computed from and the defect that would turn it red. A verifying subagent audits that
   provenance; it is not handed the commands and their expected outcomes, because a suite that
   generates its own `PASS` rows exits 0 and a re-run confirms the fabrication.
7. **Record.** Append one entry to `journal.md`. Update `state.json` -- it is the single
   status of record; `index.md` carries no status to update. Never silently drop a problem.
8. **Commit.** One atomic commit with the stage's message, including code, config, and plan
   files.

Repeat until every stage is `DONE` or terminally deferred, then **sweep `backlog.md`**: attempt
what is now resolvable, leave the rest.

## Triage -- when something fails

**1. Light** -- self-contained and fixable: a failing unit test, a lint or type error, a missing
import, a small logic bug in code you just wrote.
-> **Delegate to a subagent.** Give it the failing command and its full output, the relevant
paths, the stage goal, and a crisp deliverable. Re-run verification when it returns. **Cap at 2
attempts**, then treat it as heavy.

**2. Heavy** -- needs an architectural decision, spans many files, blocked externally, or already
survived a fix attempt.
-> **Defer to `backlog.md`.** Self-contained entry. Do not grind, do not halt.

**3. Wrong gate** -- the implementation is correct and the *criterion* is the defect: it gates on
unmeasured noise, its evidence cannot be collected in this environment, its precondition turned
out false, or its own fix lives in a later stage.
-> **Amend it.** Deferring a wrong gate does not un-gate the stage; it just blocks.

**4. Unmeasurable** -- the criterion is right, the implementation may be right, and the measurement
cannot be produced from this run's own inputs: the artefact does not exist yet, the extraction path
was never built, or the check has no way to see the defect it names.
-> **Record it as `NOT MEASURED` and let it block.** Never substitute a literal, a default, a band
midpoint, or a row generated to meet a floor. `NOT MEASURED` on a GATE is the honest answer and it
is cheaper to correct than a false `PASS` that later stages build on. This is not a wrong gate, so
the amendment rule does not apply.

### The amendment rule

**Amendable** -- criteria *about measurement*: a threshold, a tolerance, a sample count, a corpus
assumption, a target value, a false precondition.

**Never amendable** -- criteria *about correctness*: a passing test, a byte-identity or
data-integrity invariant, a security property, a structural contract, an explicit user
directive. **If in doubt, it is not amendable** -- defer to `backlog.md` instead.

An amendment requires all four:

1. Evidence in `journal.md` showing the criterion is the defect (e.g. a null A/B proving the
   gate fires on noise; a query proving the witnesses do not exist in this environment).
2. An entry in `decisions.md` quoting the original text verbatim and stating the replacement.
3. The original struck in place -- `~~old text~~ -> new text` -- never deleted.
4. The stage's disposition recorded in `state.json`.

Weakening a correctness criterion to make a stage pass is the one thing this protocol forbids
outright.

## Disposition

- Core goal met (with or without a deferral) -> **DONE**, note the backlog reference, continue.
- A deferred item is essential to *this* stage -> **BLOCKED**, list the backlog ids in
  `blocked_by`, continue to the next independent stage.

**BLOCKED is not terminal and does not propagate.**

- A stage is BLOCKED only by **its own** unmet gate. If a dependency is BLOCKED, this stage
  stays **PENDING** -- do not mark it BLOCKED, and do not burn an invocation recording that.
- **A stage may not stay BLOCKED on a backlog item that is RESOLVED.** When a backlog item
  flips to RESOLVED, revisit its origin stage in the same commit and either mark it DONE or
  name the gate still unmet.
- Stop the run only when no stage can start.

## Guardrails

- Keep every commit in a working, buildable state.
- **Never weaken, skip, or delete a test to make it pass.** If a test is genuinely wrong, fix it
  correctly and record it in `journal.md`.
- **Never generate an artefact to satisfy a declared count.** A floor on the number of checks,
  tests or rows exists to stop a suite from silently shrinking. Padding it with rows that always
  pass turns that guard into a rubber stamp, and the floor can then never be missed. If fewer can
  be measured, record the shortfall.
- **A check that cannot fail is not a check.** A status must be derived from a measurement of this
  run's own inputs. A test whose expected value was copied from the implementation's output detects
  change, not correctness -- and a gate whose implementation is imported only by tests has never
  run.
- Never use `git commit --no-verify`.
- **A commit whose diff touches only plan files uses a `docs(plan):` message** describing what
  was recorded. Never sign a bookkeeping diff with a stage's `feat:`/`fix:` message -- it makes
  git history read as though the stage shipped.
- Don't expand a stage's scope to chase a heavy problem. That is what the backlog is for.
- You may be executing a plan that is wrong about something. Planning happened before
  measurement. Halting on a wrong gate wastes the run; silently passing it destroys the audit
  trail. Amending it, with evidence written down, is the intended behavior.
